## Почему результат curl отличается

Наш граф раскрывает обязательные зависимости из поля `D` индекса.
apk дополнительно учитывает условную автоматическую установку из поля `i`.
У пакета `ssl_client@1.36.1-r31` записано:

```text
P:ssl_client
V:1.36.1-r31
D:so:libc.musl-x86_64.so.1 so:libcrypto.so.3 so:libssl.so.3
i:busybox=1.36.1-r31 libssl3
```

В графе curl присутствуют `busybox=1.36.1-r31` и `libssl3`, поэтому apk
автоматически включает `ssl_client`. Он не является дополнительным
обязательным ребром `D` curl и не добавляется нашим анализатором.
Все собственные зависимости ssl_client уже содержатся в построенном графе.
Проверочный инструмент подтверждает условия `install_if`, доступность
зависимостей и их положение раньше дополнительного пакета в плане apk.

Также наша сортировка выбирает лексикографически первый готовый пакет,
тогда как apk использует порядок своей транзакции. Например, brotli-libs
у нас стоит вторым, а в плане apk - шестым; его зависимость musl в обоих
случаях идёт первой. Эта перестановка допустима.

## Воспроизведение

В Linux с Docker и установленным `requirements.txt`:

```console
python -m tools.compare_apk
```

Инструмент печатает исходный план apk и результаты сравнения трёх пакетов.
Необъяснённое расхождение, потеря обязательного пакета или неверный порядок
вызывают код завершения 1. Известные дополнения принимаются только после
проверки условий по метаданным, а не по заранее заданному имени пакета.
Репозиторий обновляется, поэтому версии и последовательности будущего
запуска могут отличаться от зафиксированных здесь.
